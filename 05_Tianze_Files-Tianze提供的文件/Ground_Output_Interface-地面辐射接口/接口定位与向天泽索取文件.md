结论：原代码确实为 Hao 和 Linrui 分开输出；同一次计算、同一个 Linrui CSV 中又用不同列区分普通与半透明组件。用户关于“一个文件中已分开”的理解有代码依据。是否包含三种安装形式，则取决于文件：当前三个原始 notebook 各自对应一种安装形式，默认输出三个不同的 Linrui CSV，不是一个原文件统一计算三种安装形式。

## 先看这个接口

三个新版文件都有同名入口：

```python
hao_hourly, ground_summary = model_for_optimization(
    candidate_design, scenario, module_specification, array_specification,
    calculate_linrui=True,  # 地面辐射，供 Linrui 后续作物计算
    calculate_hao=False,    # 本次若不需要板面结果，可关闭这一项
)

ordinary_ground_energy = ground_summary["conventional"]["ground_total_incident_energy_Wh_period"]
semi_ground_energy = ground_summary["semi_transparent"]["ground_total_incident_energy_Wh_period"]
```

`hao_hourly` 与 `ground_summary` 这两个返回值，区分的是板面输出与地面输出。普通/半透明的区分位于 `ground_summary` 内部。字典中的 total 是选定时段、评价土地范围内的总入射能量，单位 Wh，尚未按面积归一化。

源码导出在 `source_exports/`。它们只用于定位、保留原代码和行号，包含原文件末尾的计算单元，不应直接当作无副作用的库导入。原始文件未修改。

## 同一 CSV 里的区分字段

`save_selected_results(...)` 会把上面的嵌套字典展开为六列：

| 组件 | 原 CSV 列名 |
| --- | --- |
| 普通，直射 | `conventional_ground_direct_incident_energy_Wh_period` |
| 普通，散射及反射贡献 | `conventional_ground_diffuse_incident_energy_Wh_period` |
| 普通，总量 | `conventional_ground_total_incident_energy_Wh_period` |
| 半透明，直射 | `semi_transparent_ground_direct_incident_energy_Wh_period` |
| 半透明，散射及反射贡献 | `semi_transparent_ground_diffuse_incident_energy_Wh_period` |
| 半透明，总量 | `semi_transparent_ground_total_incident_energy_Wh_period` |

这六个地面数值是“两种组件×三个辐射分量”，不能仅按列数理解成六个光伏安装组合。Hao 文件中的四个能量列则是“两种组件×正背面”，也不等同于四种安装方案。用户转述 Hao 已完成的四组研究方案仍按固定普通、固定半透明、跟踪普通、垂直普通识别。

## 已有 CSV 时怎样读取

新建的 `tianze_ground_reader.py` 只读取已有数据，不导入 bifacial-radiance，也不启动 Radiance：

```python
from tianze_ground_reader import read_ground_csv

records = read_ground_csv("Linrui_fixed_tilt_scenarios.csv", "fixed_tilt")
ordinary = [row for row in records if row["panel_type"] == "conventional"]
semi = [row for row in records if row["panel_type"] == "semi_transparent"]
```

它保留原时段、来源和单位，检查数值及直射＋散射＝总量，不把时段总量伪装成逐日数据。
